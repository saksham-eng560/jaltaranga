## 1. Summary

- **Routing** (`routing/`): turns flood forecasts and depth rasters into road status (red/amber), time-dependent safe
  walking routes, capacity-safe shelter assignment, the "avoid" list and the death-trap counterfactual, and `T_hero`
  (the demo moment).
- **Alerts** (`alerts/`): slot-filled Hindi/English/SMS dispatch cards. The LLM (Bedrock Nova) only writes sentence
  frames and never types a fact; numbers and names come from slots. Includes a 6-check validator with per-field template fallback,
  Polly (Kajal) audio, SNS email, and a draft → approve → ack lifecycle.
- **Shared contracts** (`shared/py/jt_shared`): pydantic models for every SHARED_RESOURCES §5/§11 schema, constants,
  S3 key naming, time utilities, local/S3 IO and a tiny HTTP router. It also holds the names Vaibhav's `ml/` uses.
- **Infra** (`infra/`): one SAM template (`infra/template.yaml`, generated by `infra/build_template.py` from
  `base.yaml` + `sections/*.yaml`). It is deployed as stack `jt-demo`.
- Tests: 136 offline tests (`pytest`, ~30 s), with no AWS needed.

## 6. Safety rules (don't break these)

- A route is only safe if `exit + 30 min ≤ close_at` for every edge. Amber uses the `hi_m` window max over (t, t+2 h].
- No shelter is ever assigned more than its free beds. `unreachable.json` is always written.
- The LLM never emits digits, names or phone numbers. Any validator failure falls back to the template for that field.
  Phones allowed: 1077, 112.
- `check_invariants` runs inside precompute. Don't bypass it.
